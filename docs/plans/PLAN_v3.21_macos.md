# PLAN v3.21 — 자동 풀어 보기 + 일일 도전 9판/3개월 달력 (macos)

> platform: macos · 버전: 3.21.0 · 작성: 2026-08-14 · 근거: 사용자 제안(자동 풀이 재생, 일일 도전 8~10판 + ±1개월 달력 + 월 통계) + 타 프로그램 조사(MS Solitaire Collection 데일리 챌린지/달력/월 배지, MobilityWare show-me-how-to-win, FreeCellGodot 이동 시뮬레이션, PySolFC 데모/통계) → 사용자 확정(A+B+C+D, 일일 9판, FreeCell 계열 4종만 풀이)

## 1. 개요

v3.20에서 도입한 `FreeCellSolver`(승리 가능 판정)를 확장해 **풀이 이동 시퀀스를 얻는 `solve()`**를 제공하고, 이를 **애니메이션 재생(자동 풀어 보기)**으로 보여준다. 동시에 데일리 챌린지를 **하루 9판 묶음**으로 확장하고, **현재 달 ±1개월(3개월) 달력**을 제공하며, **월간 점수/별 통계 + 월간 완료 배지**를 붙인다. 마지막으로 FreeCell 계열 딜에 **결정적 난이도 태그**를 단다.

- **A. 자동 풀어 보기**: FreeCell 계열 4종 — 현재 판을 솔버가 처음부터 끝까지 푸는 과정을 실제 이동 애니메이션으로 재생. + 완료 후 **내 이동 리플레이**(FreeCellGodot 방식).
- **B. 일일 도전 9판**: 12종 중 결정적 무작위 9판. 날짜 달력은 현재 달 기준 **이전 1달 + 현재 + 다음 1달** 3개월(결정적 생성이므로 미래 달도 존재). 판당 별점(승리/시간/이동 3점) + **월 합계 통계**(총 별/완료율/변형 분포).
- **C. 난이도 태그**: 솔버 소요 노드/깊이 기반 결정적 난이도(쉬움/보통/어려움), FreeCell 계열 4종.
- **D. 월간 완료 배지**: 월 도전 완료율 기반 브론즈/실버/골드/다이아몬드 + 달력 트로피(완료 별 표시).

## 2. 결정 사항

- **solve 예산**: 재생은 사용자 명시 요청이므로 기본(400k/4s)보다 큰 **2,000,000 노드 / 20.0s / 60,000 깊이**. 실측(2026-08-14): #50 유효 해 703 이동이 16.6초 소요 → timeLimit 15→20초로 결정. #10은 유효 해가 134초 걸려 재생 예산 밖 — "이 판은 풀이를 찾지 못했습니다" 안내 + 난이도 미측정. 실패 시 nil → "이 판은 풀이를 찾지 못했습니다" 안내.
- **재생 방식**: 솔버가 반환한 `[Move]`를 순차 `apply` + 보드 애니메이션. 재생 전 스냅샷 보존(재생 시작 상태), 중단/종료 시 원래 상태로 복원. 재생 중 조작 잠금.
- **리플레이**: 완료 게임의 실제 이동 기록(undo 스택 역순이 아닌 전방 기록)을 `[Move]`로 유지 → 재생 버튼으로 시청. 자동 완성(autoFinish) 이동 포함 여부: 포함.
- **일일 도전 9판 구성**: `DailyChallenge` 확장 — 날짜 시드로 12종 중 9개 변형을 결정적으로 샘플링(중복 없음, 순서 결정적). 각 변형의 게임 번호는 기존 `DailyDeal.gameNumber(for:variant:)` 재사용. 오늘 9판 중 미완료만 표시/재도전 가능.
- **3개월 달력**: 달력 월 이동(◀▶)은 현재 달 ±1개월 제한. 날짜 셀에 해당일 9판 완료 상태(별 합계 N/27, 트로피) 표시. 과거 날짜도 재도전 가능(결정적 시드).
- **월 통계**: 해당 달의 9판×일수 중 (완료 판수/총 판수, 별 합계, 변형별 완료 분포, 완료율). 기존 `ChallengeStore` 확장(판별 기록) + 새 월 집계 계산.
- **난이도 판정**: `solve()`의 노드 수/깊이 기반 — 노드 < 20k: 쉬움, < 150k: 보통, 그 외: 어려움. 미해결(예산 초과)은 "난이도 미측정".
- **월간 배지**: 해당 월 완료율(완료 판/가능 판) 기준 — 25% 브론즈 / 50% 실버 / 75% 골드 / 100% 다이아몬드. 업적과는 별도 월간 트로피 표시(달력 헤더).
- **롤백**: `git revert` + 해당 신규 파일/확장 제거. 기존 저장 구조 호환(새 키만 추가).

## 4. 구현 단계 (T-번호)

- [ ] T-210: `FreeCellSolver.solve(gameNumber:variant:budget:) -> [Move]?` — DFS가 성공 경로의 이동을 수집(프레임 스택 경로). `isWinnable`은 `solve() != nil`로 재구현. 재생용 예산 `ReplayBudget`(2M/15s/60k). 테스트: #1/#2/#50 풀이가 실제 적용 시 승리 도달, 미해결 #500 nil, 예산 0 nil.
  - **버그 수정 기록 (T-210 진행 중)**: 
    1. `generalMoves`의 열→열 이동 검사가 `run.first`(전체 bottom) 기준이었음 — 단일 이동(1장)은 `run.last`(top), 그룹 이동은 `run[run.count-count]`(이동 그룹 bottom) 기준이어야 함. → 무효 이동 생성으로 경로가 실제 게임에 적용 불가했던 버그 수정.
    2. 그룹 이동이 `cardCount: maxCount` 하나만 생성 — 목적지에 맞는 그룹 bottom이 maxCount보다 작은 경우 중간 크기 그룹 이동을 놓쳐 해를 못 찾음. → maxCount부터 2까지 bottom 검사로 유효한 최대 그룹 생성으로 수정.
    3. **IDDFS 도입 시도 → 실패**: 깊이 제한을 100→200→… 점진 증가하며 visited를 단계마다 초기화하면, FreeCell의 거대한 상태 공간 때문에 첫 단계(깊이 100) 탐색이 시간 예산을 소진해 이후 단계 진행 불가. **단일 DFS로 회귀**.
    4. **진행(홈 카드 증가) 없는 경로 가지치기**: 단일 DFS가 깊이 60k까지 하강하며 비현실적으로 긴 경로(#1: 31666, #2: 60029, #100: 2052 이동)를 우연히 찾는 문제 발견. `Frame`에 `homeCount`/`stagnantDepth` 추가 — 홈 카드가 `maxStagnantDepth`(80) 이동 이상 증가 없으면 그 경로 백트래킹. → **#1: 950, #2: 415 이동**으로 단축, 모두 유효.
    5. **실측 결과 (2026-08-14)**: #50은 유효 해 703 이동 존재하나 **16.6초** 소요(재생 예산 15초 초과). #10은 2553 이동 해가 **134초** 소요 — 재생 예산으로 사실상 불가능. 이전 "1.5M/10s에서 풀림" 기록은 무효 이동 기반 가짜 해로 판단. → 재생 예산 `timeLimit` 15→**20초**로 조정(#50 해결), #10은 "난이도 높음(미해결)"으로 분류(자동 풀어 보기 안내 문구).

- `git revert`. 신규 파일(FreeCellSolver 확장, Difficulty, 챌린지 9판/달력) 제거. 저장 구조는 새 키(`challenge.multi.*`)만 추가라 기존 데이터 무손상.

## 7. 성능/영향

- solve 재생은 사용자 명시 실행 시 1회 최대 ~15s(백그라운드). 게임 진행 무관.
- 데일리 9판 구성/달력/월 통계는 결정적 계산 — 수 ms.
- GameCore 결정론 유지(시드 기반).
